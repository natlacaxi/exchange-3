Ce login est IDENTIQUE pour tous les services. Pour un nouveau service (cloud, map, music...) :
  1. copier ce dossier dans le depot du service ;
  2. changer service.json (id, name, tag, color), les icones et manifest.webmanifest ;
  3. ajouter services/<id> dans la Realtime Database d'itn-2 (name, url secrete, profile, firebase{...}) ;
  4. si le service a un profil a creer, ajouter sa fonction dans PROFILES (index.html).
index.html ne change pas.

Fonctionnement
- Session ENREGISTREE sur itn-2 (meme domaine que le portail ITN : une connexion dans ITN ouvre tous les services sans rien retaper).
- Session valide : lecture de services/<id> dans Firebase -> l'adresse secrete est chargee dans un iframe plein ecran -> le site est ouvert.
  L'adresse secrete n'est ecrite nulle part dans ce code : elle n'est lue qu'apres connexion validee.
- Pas de session : carte de connexion / creation de compte, puis meme chemin.
- Chaque service a ses propres identifiants internes, derives du compte (cle secrete par service dans users/<uid>/sso/<id>) :
  un changement de mot de passe n'a aucun effet sur eux. Les comptes des autres services se creent tout seuls en arriere-plan.
- Deconnexion dans un service = deconnexion de la session enregistree.
- Installation de l'appli : on installe CE login ; il rouvre directement le service tant que la session est enregistree
  (sur iPhone/iPad l'appli installee a son propre stockage : une connexion a refaire une fois dans l'appli).

Securite : le code d'un site GitHub Pages reste lisible par toute personne connectee. Ce qui est protege : l'acces aux donnees (regles Firebase),
la revelation de l'adresse (connexion obligatoire) et les droits admin (code admin + cle secrete, voir firebase-prive.zip).
